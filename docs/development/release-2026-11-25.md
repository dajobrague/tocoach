# Release 2026-11-25 — biseries, forms follow-ups, chart sections

Source: call with Jose Carlos after the 2026-11-18 release, plus David's
review rounds on 2026-11-25. Trainer-facing summary lives in the "what's new"
modal: `features/trainer/whats-new/releases.ts` (`2026-11-25-biseries`).

## Before deploying

1. **Apply the migration in production first**:
   `supabase/migrations/20261125120000_clients_portal_locked.sql`
   (adds `clients.portal_locked boolean NOT NULL DEFAULT false`).
   `GET /api/client/bootstrap` selects that column; deploying the code without
   it makes the client app start without the client's profile.
2. `npm run type-check`, `npm run lint:check`, `npm run test`, `npm run build`.
3. Push `main`. No other migration, no new environment variable.

Side effect to expect on deploy: initial forms submitted since Nov 18 are all
"unreviewed", so they appear in trainers' Inicio board and those clients see
the thank-you card until the trainer marks them reviewed.

## What changed

### Biserie / triserie / circuito (alternating sets)

Two to six consecutive strength exercises of a session that the client
performs alternating one set of each. Named by size: 2 = Biserie,
3 = Triserie, 4–6 = Circuito (`altGroupName`, `ALT_GROUP_MAX = 6`).

- **Data**: every member carries the same string in
  `session_exercises.metadata.alt_group`. A group is a run of neighbours
  (by `exercise_order`) sharing that key — there is no group table and no
  migration. Pure logic and wording: `lib/training/alt-groups.ts`.
- **Trainer** (`features/trainer/training/programa/session-row.tsx`):
  - "Hacer biserie" button beside "Añadir ejercicio" → pick mode with
    checkboxes; the selection is always a consecutive range.
  - A group renders as one tray with its name and "Deshacer".
  - Drag and drop: drop between two members to join; dotted zones appear
    while dragging — at the tray bottom (add as last), below the tray (take
    out), and at the right end of a loose row (make a new biserie).
  - Saved through `PATCH …/sessions/[sessionId]/exercises` with
    `{ groups: [{ id, alt_group }] }`, optionally with `reorder` in the same
    request. The `PUT` on an exercise rebuilds `metadata`; it preserves
    `alt_group` explicitly.
- **Client**:
  - Session page shows the group as one card
    (`GroupFocusCard` in `active-session-view.tsx`).
  - `components/client-dashboard/exercise-log/alternating-log-screen.tsx`:
    one screen for the group, filled series by series. It reuses
    `ExerciseSetRow`, so per-series video, RIR and per-side reps behave as in
    the single-exercise screen. One log per exercise is still written, so
    history, records and charts are unchanged.
  - `exercise-info-sheet.tsx`: bottom sheet with image, demo video,
    prescription and trainer note, opened from an exercise name.
- **Rest**: the last exercise's rest is shown as the rest after each series
  of the group.
- **Known gaps**: no linking in program templates' own editor; the tray gives
  no highlight when a row is dropped between two members (only the dotted
  zones highlight); cardio exercises cannot be grouped.

### Training

- "Siguiente" after finishing an exercise opens the next pending one
  (forward only); Compartir becomes a small icon when there is a next one.
- Share card draws the tenant logo as uploaded (no circular mask).

### Forms

- Trainer can correct a client's answer (number, 0–10 scale, rating, text)
  from the response view: `PUT /api/forms/responses/[clientId]/[responseId]`
  with `answer_patch`; sets `metadata.edited_by_trainer_at`.
- Initial form: opens by itself on first visit, thank-you card until the
  trainer reviews it, listed in Inicio ("Check-ins y formularios por
  revisar"), "Marcar revisado" on the profile card.
- Plan access: `clients.portal_locked`. New clients are created locked only
  when the trainer's initial form is active; "Dar acceso al plan" in the
  profile header unlocks. **The gate is in the client UI only**
  (`ClientDataProvider` + bottom nav); API routes do not check it.
- Daily habits window: the server now honours
  `tenants.features.habit_log_days` (it hard-coded about five days).

### Charts

- Optional `section` per chart (`ChartConfig.section`, in the zod schema so
  it survives saves); tabs on trainer and client views. Clients with
  customised charts keep their own copy.
- Line/area Y axis capped at one decimal.

## How it was verified

Type-check, lint and the unit suite, plus a walkthrough on the local stack as
trainer and as a client. Not exercised in a browser: a circuit of four or
more exercises, cardio dropped onto a group, and a real video file uploaded
from the biserie screen (a dummy file did attach).
